RFID Access Control System — Electric Lock Version

Arduino UNO · RC522 RFID · DS3231 RTC · 5V Relay Module · Electric Lock · SPI · I²C

Case Study

From RFID identification and simulated movement to time-aware control of a physical electric locking mechanism.

Problem Objective Evolution Components Power Communication RTC Relay Authorization Architecture Workflow Testing Outcome Documentation

The Access-Control Problem

An access-control system must identify a credential, determine whether access is authorized, control a physical entry mechanism, provide feedback, and return to a secure state after the access interval expires.

A servo motor is useful for validating the control sequence, but it remains a low-power simulation of a lock. A more realistic system requires an electrical switching stage and a separately powered locking mechanism.

The upgraded design therefore introduces a relay-controlled electric lock and a real-time clock. These components move the project from simple actuator movement toward a time-aware embedded access-control architecture.

Engineering Motivation

The second version preserves the validated RFID and authorization logic while replacing the simulated actuator with a switching circuit that can control a real electric lock.

Upgrade Objective

The objective was to extend the RFID prototype into a system capable of controlling an electric lock through a relay module and associating each access attempt with an accurate date and time.

The system was designed to initialize all connected modules, read an RFID credential, obtain the current timestamp, evaluate authorization, switch the lock circuit, preserve the secure default state, and produce understandable status output.

The upgrade combines RFID communication, real-time clock integration, relay control, external-load switching, timing logic, embedded state management, and access-event analysis.

System Scope

The project focuses on local RFID authorization, physical lock control, timestamped system output, and automatic return to a locked state. Permanent database logging and network-based administration remain outside the current version.

Evolution from the Servo Prototype

The first version validated the essential access-control cycle: card detection, UID reading, authorization, actuator response, status feedback, and automatic reset.

The second version retains that logical foundation but changes the actuation and timing layers. Servo-angle control is replaced by relay switching, and a DS3231 module adds an independent source of date and time.

Hardware Components

Each component has a separate responsibility within the complete access-control chain.

Controller

Arduino UNO

Executes the authorization logic, coordinates SPI and I²C communication, controls the relay input, manages timing, and generates status output.

Identification

RC522 RFID Reader

Detects compatible RFID cards and tags, reads the UID, and sends the identifier to the controller through SPI.

Timekeeping

DS3231 RTC

Maintains accurate date and time independently of the main program cycle and retains timekeeping through its backup battery.

Switching

5V Relay Module

Converts a low-power digital control signal into switching action on the separate electric-lock circuit.

Actuator

Electric Lock

Represents the physical access mechanism whose locked or unlocked state is controlled through the relay contacts.

Power

Power-Supply Stage

Provides the voltage and current required by the controller, logic modules, and electric lock without forcing the Arduino output pin to power the load directly.

Power and Electrical Separation

The electric lock is not powered from an Arduino digital pin. The controller supplies only the logic signal required by the relay module.

The relay contacts switch the external lock circuit, allowing the load to use a power supply selected for the electrical requirements of the lock.

This separation protects the low-power control logic from the higher current demanded by the physical actuator and makes the system architecture suitable for a real locking device.

Electrical Constraint

The relay contact rating, lock voltage, lock current, power supply, wiring, and default locked state must be compatible. These values are determined by the selected physical lock rather than by the Arduino alone.

Communication Protocols

The system combines two communication buses and one digital control interface without mixing their responsibilities.

SPI — RFID Communication

The RC522 exchanges card-identification data with the Arduino through the SPI bus. Dedicated chip-select and reset lines allow the controller to initialize and address the reader.

I²C — RTC Communication

The DS3231 uses shared SDA and SCL lines to provide date and time information with minimal additional wiring.

Digital Output — Relay Control

A configured output pin changes the relay input state. The software must account for whether the selected relay module uses active-HIGH or active-LOW logic.

RTC Timekeeping

The DS3231 introduces an independent time reference into the access-control process. The controller reads the current date and time when an RFID credential is processed.

The timestamp can be included in Serial Monitor output or forwarded to a future logging module. In the current design, the RTC provides time-aware event output but does not by itself create permanent access records.

The backup battery allows the RTC to preserve time even when the main system is disconnected, avoiding the need to reset the clock after every power interruption.

Timestamped Event Structure

Date and time · scanned UID · authorization result · relay state · lock state.

Relay Control

The relay module acts as the switching interface between the controller and the lock circuit. The Arduino changes only the relay input state; the relay contacts determine whether current reaches the lock.

The control logic defines a secure initial relay state during startup, activates the relay only after successful authorization, keeps it active for a defined interval, and then returns it to the locked state.

Active-HIGH and active-LOW relay modules require opposite logic levels. The software state names should therefore describe the physical result—locked or unlocked—rather than relying only on HIGH and LOW.

Electric Lock Operation

The physical behavior depends on the selected lock type and on whether the relay uses normally open or normally closed contacts.

The design must explicitly define the default state during normal operation and during power loss. A fail-secure lock remains locked without power, while a fail-safe lock releases when power is removed.

The prototype therefore treats lock behavior as a system-level property that combines hardware selection, relay wiring, control polarity, timing, and safety requirements.

Authorization Logic

After detecting a card, the system reads and formats its UID. The identifier is compared with the locally defined list of authorized credentials.

A valid credential produces an access-granted event, relay activation, temporary unlocking, and automatic relocking. An unknown or invalid credential produces an access-denied event while the relay remains in the secure state.

The access decision and the current timestamp are shown together so that identification and timekeeping remain part of the same operational event.

Secure Default Behavior

Initialization, invalid cards, communication errors, and the end of every access interval must all return the system to a known locked state.

System Architecture

The system is organized as a sequence of specialized layers that move from identification to physical access control.

Identification Layer

RC522 card detection and UID acquisition through SPI.

Time Layer

DS3231 date and time acquisition through I²C.

Decision Layer

UID comparison, access decision, and event-state generation.

Switching Layer

Relay control, timing interval, and secure reset.

Physical Layer

Externally powered electric locking mechanism.

Operational Workflow

Each access attempt follows a controlled sequence from hardware initialization to secure reset.

1

Initialize Hardware

SPI, RC522, I²C, DS3231, relay output, and Serial Monitor are initialized.

2

Set Locked State

The relay is placed in the predefined secure state before card scanning begins.

3

Detect RFID Card

The RC522 waits for a compatible card and begins UID reading.

4

Read Timestamp

The current date and time are obtained from the DS3231 module.

5

Evaluate UID

The scanned identifier is compared with authorized values.

6

Control the Relay

Valid access activates the lock-control circuit; invalid access leaves it unchanged.

7

Display Event Status

Timestamp, UID, access decision, and system state are reported.

8

Relock and Reset

The relay returns to the secure state and the RFID reader is prepared for the next card.

Testing Scenarios

Testing focuses on the complete interaction between identification, timekeeping, switching, and physical lock behavior.

Authorized Card

The UID is accepted, the current timestamp is read, the relay changes state, the lock is released for the defined interval, and the system automatically relocks.

Unauthorized or Unknown Card

The UID is displayed with an access-denied result while the relay and electric lock remain in the secure state.

Automatic Relocking

The relay is verified to return to the locked state after the configured access interval.

RTC Persistence

Date and time are checked before and after interruption of the main system power to confirm backup timekeeping.

Power Interruption

Relay and lock behavior are examined during shutdown and restart to verify the selected fail-safe or fail-secure design.

Repeated Access Attempts

Consecutive valid and invalid scans are used to evaluate stability, card reset, timing, and relay-state recovery.

RTC Communication Failure

The system response is evaluated when time data is unavailable, ensuring that a clock failure does not produce uncontrolled relay activation.

Relay Polarity Verification

Startup and active states are checked against the selected relay module to prevent unintended unlocking caused by reversed HIGH/LOW assumptions.

Key Engineering Decisions

Relay Instead of Direct Load Control

The controller never powers the electric lock directly. Switching is delegated to a relay stage designed for a separate load circuit.

Independent Time Source

The DS3231 provides stable date and time without depending on the Arduino program runtime or repeated manual clock setup.

Secure Startup State

Relay initialization occurs before normal scanning so that startup does not temporarily place the lock in an undefined state.

Physical-State Naming

The design describes locked and unlocked states explicitly, avoiding ambiguity caused by different relay polarities and contact configurations.

Results and Evaluation

The upgraded system defines a complete access-control chain from RFID credential detection to relay-controlled operation of an electric lock.

The DS3231 adds a reliable temporal dimension, allowing access decisions to be presented as timestamped system events rather than isolated UID comparisons.

The project also exposes the engineering differences between controlling a low-power servo and controlling a separately powered lock circuit: relay polarity, contact selection, power requirements, secure default state, and power-loss behavior become central design decisions.

System Value

The second version connects identification, authorization, timekeeping, electrical switching, and physical access control within one embedded-system architecture.

Project Strengths

  • Preserves the validated RFID authorization workflow.
  • Replaces simulated movement with physical lock control.
  • Separates low-power logic from the lock load circuit.
  • Adds independent RTC-based timekeeping.
  • Supports timestamped access-event output.
  • Defines secure initialization and automatic relocking.
  • Integrates SPI, I²C, and digital switching in one system.

Current Limitations

  • Authorized UIDs are locally defined rather than managed through a database.
  • Timestamped events are not permanently stored in the current design.
  • Lock behavior depends on the selected electric-lock type and power configuration.
  • The current version does not include network administration or remote access management.
  • Advanced protection against cloned RFID credentials is outside the prototype scope.
  • Long delay-based unlocking can temporarily block other program tasks unless replaced with non-blocking timing.

Future Development

The electric-lock architecture provides a basis for a more complete access-control platform.

  • EEPROM, SD-card, or database storage of access events.
  • Non-blocking unlock timing based on the system clock.
  • Buzzer, LED, or display feedback.
  • Card enrollment and removal through an administrator mode.
  • Door-position sensor and lock-state verification.
  • PIN plus RFID multi-factor access.
  • ESP8266 or ESP32 connectivity for remote monitoring.
  • Web dashboard and centralized credential management.
  • Backup-power monitoring and controlled shutdown behavior.
  • Enclosure, cable protection, and production-level electrical safety.
