The Mathematical Problem

Systems of linear equations appear in engineering, computation, modeling, optimization, simulation, and data analysis. Small systems can often be solved manually, but larger or repeatedly evaluated systems require reliable numerical methods and a clear way to inspect the computational process.

Direct and iterative methods solve the same class of problems in fundamentally different ways. Gaussian elimination transforms the system into an equivalent form and obtains a solution through elimination and substitution, while Jacobi and Gauss–Seidel generate successive approximations until a stopping criterion is satisfied.

The practical challenge is not only to calculate a final solution, but also to validate the input, detect unsuitable conditions, observe convergence, track numerical error, and present intermediate results in a form that can be understood and compared.

Project Motivation

The project transforms three numerical methods from isolated theoretical procedures into one interactive environment where the user can enter a system, choose a method, follow every computational step, and evaluate the behavior of the solution process.

Project Objective

The objective was to develop a desktop application that implements direct and iterative methods for solving linear systems while preserving the mathematical logic behind each method.

The application supports structured input, parameter configuration, diagonal-dominance validation, step-by-step iteration tracking, error calculation, convergence monitoring, and graphical visualization.

The project combines numerical computation, software design, user-interface development, algorithmic validation, and experimental comparison within one system.

Core Design Principle

The application does not hide the numerical process behind a single result. It exposes intermediate values, iteration counts, errors, and convergence behavior so the user can understand how the result was obtained.

Implemented Numerical Methods

The project implements one direct method and two iterative methods, allowing different computational strategies to be studied within the same application.

Direct Method

Gaussian Elimination

Transforms the coefficient matrix into upper triangular form and determines the unknown variables through backward substitution. Partial pivoting improves stability and avoids division by zero or extremely small pivot values.

Iterative Method

Jacobi Method

Generates a new approximation using only values from the previous iteration. The method provides a clear independent update structure and allows the full convergence process to be recorded.

Iterative Method

Gauss–Seidel Method

Updates each variable immediately and uses the newest available values during the same iteration. For suitable systems, this often produces faster convergence than the Jacobi method.

Convergence and Error Analysis

Iterative methods generate a sequence of approximations whose behavior must be evaluated through a stopping condition. The application calculates the difference between successive approximations and stops when the selected tolerance is satisfied or the maximum number of iterations is reached.

The iteration table and graph show whether values stabilize, whether error decreases, how many iterations are required, and whether the selected method converges for the given system.

Why Convergence Must Be Visible

A final numerical value alone does not show whether the iterative process behaved reliably. Preserving the approximation sequence makes the method testable, explainable, and comparable.

Method Comparison

The implemented methods solve the same class of problems but differ in computational strategy, convergence requirements, and the type of information they expose.

MethodTypeMain PrincipleStrengthLimitation
Gaussian Elimination Direct Matrix transformation followed by backward substitution. Produces a solution in a finite sequence for a valid non-singular system. Requires careful pivot handling and may accumulate floating-point error.
Jacobi Iterative Every new value is calculated from the previous iteration. Clear independent update structure and transparent iteration behavior. May converge slowly or fail to converge for unsuitable systems.
Gauss–Seidel Iterative New values are used immediately within the same iteration. Often converges faster than Jacobi for suitable systems. Convergence is not guaranteed for every coefficient matrix.

Testing and Validation

The application was tested with systems selected to examine correctness, stability, convergence behavior, and error handling.

Valid Non-Singular Systems

Systems with known solutions verify Gaussian elimination and iterative convergence.

Diagonally Dominant Systems

Suitable matrices compare Jacobi and Gauss–Seidel convergence speed and iteration count.

Non-Dominant Systems

Unsuitable matrices test warning behavior and demonstrate that convergence cannot be assumed.

Invalid and Edge Input

Empty fields, non-numeric values, zero pivots, strict tolerances, and low iteration limits test robustness.

Project Outcome

The result is a functional desktop application that solves systems of linear equations using three numerical methods and presents both final and intermediate computational results.

The project demonstrates how mathematical theory can be translated into modular algorithms, a usable interface, transparent validation, measurable error analysis, and visual interpretation.

Instead of reducing numerical methods to formulas, the application presents them as observable computational processes whose behavior can be tested and compared.

Why This Project Matters

The project combines algorithm implementation, numerical reasoning, interface design, validation, visualization, and technical explanation within one coherent system.

Project Strengths

  • Implements direct and iterative solution strategies.
  • Preserves intermediate computational results.
  • Uses partial pivoting for improved numerical stability.
  • Checks diagonal-dominance conditions.
  • Supports configurable tolerance and iteration limits.
  • Visualizes convergence and error behavior.

Current Limitations

  • The application is intended for relatively small educational and experimental systems.
  • Iterative convergence depends on coefficient-matrix properties.
  • Floating-point arithmetic may introduce rounding error.
  • The current version focuses on three methods.
  • Large-scale performance benchmarking is outside the current scope.

Future Development

The current application provides a stable base for extending the numerical laboratory with additional methods, larger systems, and broader analytical capabilities.

  • LU decomposition and Cholesky decomposition.
  • Successive over-relaxation and conjugate-gradient methods.
  • Automatic row reordering to improve diagonal dominance.
  • Residual-vector calculation and alternative error measures.
  • Import and export through CSV or spreadsheet files.
  • Performance comparison for larger systems.
  • Sparse-matrix support.
  • Additional graphs for residuals, speed, and method comparison.
  • Automatic recommendation of a suitable method.
  • Web-based or browser-accessible version.
