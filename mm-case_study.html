RFID Access Control System — Servo Prototype

Arduino UNO · RC522 RFID · Servo SG90 · SPI Communication · Embedded Control · Serial Monitoring

Case Study

A first-stage embedded prototype validating RFID identification, authorization logic, actuator control, and automatic system reset.

Problem Objective Scope Components Connections RFID Communication Authorization Servo Control Architecture Workflow Testing Outcome Documentation

The Access-Control Problem

Electronic access-control systems must identify a presented credential, determine whether it is authorized, activate or preserve the locking mechanism, provide clear feedback, and return to a secure waiting state.

Even a simplified prototype requires reliable coordination between a contactless identification device, decision logic, an actuator, and the user-feedback channel. A failure in any stage can produce an incorrect access decision or an undefined mechanism state.

The project addresses this problem through a compact RFID prototype in which identification is performed by the RC522 reader and physical lock behavior is represented by a servo motor.

Project Motivation

The servo-based implementation provides a visible and controllable way to validate the complete access cycle before considering more complex locking hardware.

Project Objective

The objective was to implement a functional RFID access-control prototype that recognizes predefined cards and translates the authorization result into a visible mechanical response.

The system was designed to read an RFID UID, compare it with two authorized UID values, open the servo mechanism when access is approved, preserve the closed position when access is denied, display the result through the Serial Monitor, and reset the reader for the next card.

The prototype combines embedded control, SPI communication, RFID identification, actuator control, timing logic, and scenario-based testing.

Core Design Principle

Every scan must produce one unambiguous result: authorized access with controlled opening, or denied access with the mechanism remaining locked.

Prototype Scope

The project represents the first functional version of the access-control system. Its scope is deliberately limited to the core identification and actuation cycle.

The authorization list is defined directly in the program, the actuator is a servo motor, and the Serial Monitor is used as the status interface. The prototype does not include remote administration, database storage, user enrollment, access history, or network communication.

This controlled scope makes it possible to isolate and verify the fundamental behavior of the system without introducing unrelated infrastructure.

Validated Core Cycle

Card detection → UID reading → authorization comparison → servo response → status message → automatic reset.

Hardware Components

The prototype uses a minimal hardware configuration in which each component has one clearly defined responsibility.

Controller

Arduino UNO

Executes the program logic, manages SPI communication, compares UID values, controls the servo, and sends status messages to the Serial Monitor.

Identification

RC522 RFID Reader

Detects RFID cards and tags operating at 13.56 MHz and provides the unique card identifier used by the authorization logic.

Actuator

Servo SG90

Represents the physical locking mechanism through controlled closed and open positions.

Credential

RFID Cards and Tags

Provide unique UID values. Two predefined identifiers are treated as authorized credentials in the prototype.

Electrical Connections

The RC522 communicates through the Arduino UNO hardware SPI pins, while the servo receives its control signal from a dedicated digital pin.

Voltage Requirement

The RC522 module is powered from 3.3 V. Connecting the reader to 5 V can damage the module or produce unreliable behavior.

RFID Communication

Communication between the Arduino UNO and the RC522 reader is implemented through the SPI protocol. The controller provides the clock and selects the reader, while data is exchanged over separate input and output lines.

The program continuously checks whether a new card is present. When a card is detected, the RC522 reads its UID bytes and transfers them to the controller for formatting and comparison.

After the card is processed, communication with the current card is completed and the reader returns to the waiting state.

Used Libraries

SPI manages the communication bus.
MFRC522 provides reader initialization, card detection, and UID access.
Servo generates the actuator control signal.

Authorization Logic

The UID of every scanned card is compared with two predefined authorized identifiers stored in the program.

When the scanned UID matches either authorized value, the system classifies the credential as valid. Any UID outside the predefined list is treated as unauthorized.

This approach is suitable for a controlled prototype because it isolates the decision logic and makes every test result easy to reproduce. It is not intended as a scalable credential- management mechanism.

Decision Rule

UID matches authorized list → access granted.
UID does not match authorized list → access denied.

Servo Lock Mechanism

The servo motor represents the physical locking mechanism. A closed position corresponds to denied or inactive access, while the open position represents temporary authorization.

When a valid card is detected, the controller moves the servo to the open position, preserves that state for a defined time interval, and then returns it to the closed position.

An invalid or unknown card does not trigger the opening cycle. The mechanism remains in the secure position while the denial message is displayed.

Automatic Relocking

The servo does not remain open after an approved scan. The timed return to the closed position completes the access cycle and restores the initial system state.

Core Functionalities

RFID Identification

Detects a presented credential and reads its unique UID.

Authorization Check

Compares the scanned UID with the predefined valid-card list.

Actuator Control

Converts the authorization result into a visible servo movement.

Automatic Relocking

Returns the mechanism to the closed position after the approved access interval.

Serial Feedback

Displays scanned identifiers and access-granted or access-denied messages.

System Reset

Completes communication with the processed card and prepares the reader for the next scan.

System Architecture

The prototype can be described through five logical layers connecting physical input, decision processing, mechanical response, and feedback.

Credential Layer

RFID cards and tags provide unique identification values.

Reader Layer

RC522 detects the card and transfers its UID through SPI.

Control Layer

Arduino executes UID comparison, timing, and state logic.

Actuator Layer

Servo represents opening, holding, and closing behavior.

Feedback Layer

Serial Monitor presents UID and access-status messages.

System Workflow

Every scan passes through the same deterministic sequence.

1

Initialize Hardware

Serial communication, SPI, RC522, and servo control are initialized.

2

Wait for Card

The reader continuously checks for a newly presented RFID credential.

3

Read UID

The identifier bytes are retrieved and prepared for comparison.

4

Compare Identifier

The UID is checked against the two authorized values.

5

Grant or Deny Access

The system selects the valid-card or invalid-card branch.

6

Control Servo

A valid card opens the mechanism; an invalid card leaves it closed.

7

Display Status

The UID and access result are shown through the Serial Monitor.

8

Reset for Next Scan

The card session is completed and the system returns to the waiting state.

Testing Scenarios

The prototype was evaluated through access scenarios that test identification, decision logic, timing behavior, actuator response, and system recovery.

Valid Card

The UID is recognized, access is granted, the servo moves to the open position, a positive status message is displayed, and the mechanism closes automatically.

Invalid Card

The UID is read but does not match the authorized list. The servo remains closed and an access-denied message is shown.

Unknown Card

A card that has never been registered in the program is processed as an unauthorized credential without changing the secure mechanism state.

Repeated Scanning

Consecutive scans verify that the previous card session is completed and that the reader correctly returns to the waiting state.

Delay and Relocking Behavior

The opening interval is checked to confirm that the mechanism remains open only for the intended duration before returning to the closed position.

Response and Feedback

The test verifies that card detection, message display, and actuator response occur in the correct sequence without an ambiguous intermediate state.

Key Engineering Decisions

Servo as a Visible Lock Model

A servo motor makes opening and closing behavior directly observable, which simplifies prototype validation.

Hard-Coded Authorized UIDs

A fixed authorization list reduces complexity and supports reproducible tests of the decision logic.

Serial Monitor as Feedback Interface

The Serial Monitor exposes scanned identifiers and decision results without requiring additional display hardware.

Automatic Return to Secure State

The mechanism returns to the closed position after every approved cycle instead of depending on an additional user action.

Project Outcome

The result is a functional first-stage RFID access-control prototype that completes the full identification, authorization, actuator-response, feedback, and reset cycle.

The system distinguishes authorized and unauthorized cards, controls a visible locking model, communicates status through the Serial Monitor, and restores the locked state after an approved scan.

The project demonstrates the practical coordination of an RFID reader, SPI communication, embedded decision logic, timing, and servo control within one compact system.

Why This Project Matters

The prototype turns an abstract access-control sequence into a complete, observable embedded workflow that can be tested at every stage.

Project Strengths

  • Clear separation of identification, authorization, and actuator response.
  • Contactless RFID credential reading.
  • Support for two authorized UID values.
  • Visible servo-based lock simulation.
  • Automatic return to the locked state.
  • Real-time UID and status feedback.
  • Compact hardware configuration and reproducible tests.

Prototype Limitations

  • Authorized UIDs are stored directly in the program.
  • The servo simulates a lock but is not a production locking mechanism.
  • Access events are not stored in a database or persistent log.
  • The prototype has no local card-enrollment interface.
  • Serial Monitor feedback requires a connected development environment.
  • Network communication and remote administration are outside the project scope.

Possible Future Development

The first version provides a stable base for expanding the prototype while preserving the validated access-control logic.

  • Persistent card storage through EEPROM or an external database.
  • Administrative card enrollment and removal.
  • Buzzer and LED feedback for access decisions.
  • LCD status display.
  • Timestamped access-event logging.
  • Combined RFID and PIN authentication.
  • Door-state or tamper sensors.
  • Network communication and remote monitoring.
